Every conversation you have with OpenCode is a session. Sessions have their own history and context — the model remembers everything said within a session, but starts fresh in a new one. A single project can have as many sessions as you like.

<AgentPrompt title="Sessions" />

## Starting a new session

There are a few ways to start a new session:

- **Type `/new`** in the prompt — works in both OpenCode Desktop and the TUI
- **Click New Session** in the left sidebar in OpenCode Desktop

The current session stays in your history. You can always go back to it.

## Sessions persist

Your session history is saved to disk. You can resume any previous session even after quitting and restarting OpenCode. Nothing is lost — if you were mid-task when you closed the app, the conversation is still there when you reopen it.

## Sharing a session

You can share any session as a public link — useful for collaborating with teammates or asking for help.

```
/share
```

This generates a unique URL (at `opncd.ai/s/<id>`) and copies it to your clipboard. Anyone with the link can view the conversation.

To stop sharing and remove the data:

```
/unshare
```

### Sharing modes

The default behavior is **manual** — sessions are private unless you explicitly run `/share`. You can change this in your config to share every session automatically:

```json
{ "share": "auto" }
```

Or disable sharing entirely:

```json
{ "share": "disabled" }
```

Disabling sharing is a good idea for sessions that involve sensitive or proprietary information. To enforce this across a team, add `"share": "disabled"` to your project's `opencode.json` and commit it.

## Listing and exporting sessions

OpenCode has CLI commands for working with session data:

```
opencode session list
```

Lists the sessions in the current project, newest first — session ID, title, and timestamp. Add `-n` to cap how many come back (`opencode session list -n 10`), or `--format json` for machine-readable output.

```
opencode session export <sessionID>
```

Exports a single session as JSON, including the full message history and metadata. If you omit the session ID, OpenCode prompts you to pick one. Add `--sanitize` to redact sensitive transcript and file data before you share the export.

`opencode session import <file>` goes the other way, restoring a session from a JSON file or URL you exported earlier.

If the `opencode` command isn't found, your CLI isn't on your PATH. OpenCode Desktop bundles one inside the app, but it doesn't add it there for you — the exercise below works without the terminal.

Ask OpenCode to list your sessions and summarize what you've been working on. You don't need to touch the terminal — OpenCode can run the commands, read the output, and give you a summary.
